# ПРОСТІР КОРИСНОГО КОНТЕНТУ — фінальна версія для GitHub Pages + Telegram Mini App

## Що це

Це готовий статичний Mini App: GitHub Pages віддає HTML/CSS/JavaScript і 15 файлів із порадами. Окремий сервер для роботи самого застосунку не потрібен.

У застосунку є:
- 15 категорій;
- 30 000 порад — по 2 000 у кожній категорії;
- персональне привітання з ім’ям Telegram-користувача;
- прихований технічний ліміт 10 порад на добу для безкоштовного режиму;
- без відображення «10/10» або іншого лічильника;
- збереження стану через Telegram CloudStorage, якщо він доступний, з локальним резервом;
- Premium-екран і Telegram Stars invoice;
- 30-денний Premium-режим безлімітних порад;
- адаптація під телефон і Telegram;
- `.nojekyll` для GitHub Pages.

## Важливе обмеження, яке не можна обійти одним GitHub Pages

GitHub Pages — статичний хостинг. Він не виконує Python/Node/PHP на сервері. Тому без окремого backend неможливо зробити на 100% захищений серверний ліміт і серверну перевірку Premium.

У цій версії:
- ліміт 10/день зберігається у Telegram CloudStorage, коли він доступний, і в localStorage як резерв;
- після успішної оплати invoice Mini App записує Premium до дати закінчення 30 днів;
- це зручно для старту, але користувач технічно може очистити локальні дані або скористатися іншим пристроєм;
- автоматичне продовження Stars-підписки не може бути надійно підтверджене самим статичним сайтом після поновлення, бо для серверної перевірки потрібен backend.

Тому цю версію слід сприймати як **повністю GitHub-only стартову версію**, а не як фінансово захищену SaaS-систему.

## Крок 1. Створіть GitHub-репозиторій

1. Відкрийте https://github.com/ і увійдіть у свій акаунт.
2. Натисніть **New repository**.
3. Назва, наприклад: `prostir-korysnoho-kontentu`.
4. Для GitHub Free зробіть репозиторій **Public**.
5. Створіть репозиторій.

## Крок 2. Завантажте файли

Розпакуйте ZIP і завантажте саме вміст папки в корінь репозиторію. Має бути так:

```text
index.html
config.js
.nojekyll
README.md
assets/
data/
bot/
```

Не кладіть `index.html` на один рівень глибше.

## Крок 3. Увімкніть GitHub Pages

У репозиторії відкрийте:

**Settings → Pages**

У **Build and deployment** виберіть:

- Source: **Deploy from a branch**
- Branch: **main**
- Folder: **/(root)**

Натисніть **Save**.

Через деякий час GitHub покаже кнопку **Visit site**. Адреса буде приблизно:

`https://ВАШ_USERNAME.github.io/prostir-korysnoho-kontentu/`

Увімкніть **Enforce HTTPS**, якщо GitHub пропонує цю опцію.

## Крок 4. Створіть Telegram-бота

1. В Telegram знайдіть **@BotFather**.
2. Натисніть Start.
3. Введіть `/newbot`.
4. Вкажіть назву, наприклад:
   `Простір корисного контенту`
5. Вкажіть username, наприклад:
   `prostir_korysnoho_bot`.
   Username має закінчуватися на `bot`.
6. BotFather видасть **токен**.

ВАЖЛИВО: токен — секрет. Не вставляйте його в `index.html`, `config.js`, GitHub або Telegram-канал. Збережіть його тільки у себе.

## Крок 5. Підключіть Mini App до бота

У @BotFather відкрийте свого бота → **Bot Settings → Configure Mini App**.

Якщо меню показує **Enable Mini App / Configure Mini App / Main Mini App**, виберіть налаштування Mini App і вставте вашу GitHub Pages HTTPS-адресу.

Для зручності також налаштуйте **Menu Button** і вкажіть ту саму адресу. Назву кнопки можна зробити:

`✨ Відкрити Простір`

Після цього користувач зможе відкривати Mini App із профілю/меню бота.

## Крок 6. Додайте бота у свій канал

Якщо хочете кнопку в дописі каналу:

1. Відкрийте свій канал.
2. Створіть новий допис.
3. Додайте посилання на бота або Mini App.
4. Для головного Mini App Telegram також підтримує прямий запуск через посилання на бота.

Найпростіший варіант для першого запуску: дайте людям кнопку/посилання на бота, а всередині бота відкривайте Mini App.

## Крок 7. Персональне ім’я

Нічого вручну налаштовувати не потрібно.

Telegram передає Mini App базові дані користувача. Застосунок бере `first_name`, а якщо його немає — `username`.

Користувач побачить, наприклад:

`Вітаємо, Олександр 💛`

Ім’я використовується тільки для відображення. Не використовуйте `initDataUnsafe` як доказ особи або як захисний механізм.

## Крок 8. Налаштуйте Premium Stars

Для цього потрібен токен бота, але він **не потрапляє в GitHub**.

На комп’ютері має бути Python 3.

Відкрийте папку ZIP і запустіть:

```bash
python bot/create_invoice_link.py
```

Якщо команда `python` не працює у Windows, спробуйте:

```bash
py bot/create_invoice_link.py
```

Скрипт запитає:

`Вставте токен бота:`

Вставте токен, який дав BotFather.

Потім запитає ціну. За замовчуванням:

`10`

Після звернення до Telegram Bot API скрипт видасть довге invoice-посилання.

Скопіюйте його.

## Крок 9. Вставте invoice у config.js

Відкрийте файл `config.js`.

Замість:

```js
premiumInvoiceUrl: "",
```

вставте отримане посилання:

```js
premiumInvoiceUrl: "https://t.me/$...",
```

Збережіть файл і завантажте оновлений `config.js` на GitHub.

## Крок 10. Що побачить користувач

Головний екран:

**ПРОСТІР**

*КОРИСНОГО КОНТЕНТУ*

«Вітаємо, Ім’я 💛»

«Порада на будь-який випадок життя»

Потім 15 категорій.

Після вибору категорії — одна порада і кнопка:

**✨ Отримати наступну пораду**

Ліміт 10 порад технічно працює, але користувачу цифра не показується.

Після ліміту:

**🌙 Поверніться трохи пізніше**

«На сьогодні ми вже підготували для вас достатньо порад. Якщо хочеться більше — ви можете підключити Преміум без щоденного обмеження.»

## Крок 11. Як працює Premium

Натискання **Підключити Преміум** відкриває Telegram invoice.

Після успішної оплати застосунок отримує статус `paid` і на цьому пристрої/у Telegram CloudStorage записує Premium на 30 днів.

Ціна зараз встановлена як 10 Stars. Змінити її можна в `config.js` і під час створення нового invoice.

## Крок 12. Перед публічним запуском перевірте 6 речей

1. GitHub Pages відкривається через HTTPS.
2. У Mini App завантажуються всі 15 категорій.
3. Відкривається випадкова порада.
4. Ім’я Telegram відображається правильно.
5. Після 10 безкоштовних порад користувач не бачить лічильника, а отримує повідомлення про паузу.
6. Premium invoice відкривається і тестовий платіж проходить.

## Що НЕ можна публікувати на GitHub

Ніколи не завантажуйте:
- токен Telegram-бота;
- паролі;
- секретні API-ключі;
- приватні ключі.

## Про якість контенту

У папці `data/` — 30 000 порад: 15 файлів по 2 000. Вони переформатовані та перероблені так, щоб кожна рекомендація була окремою практичною думкою, без старого шаблонного вступу. Для ризикових тем збережено обережні формулювання: у питаннях здоров’я, фінансів, автомобілів, цифрової безпеки та подорожей не слід сприймати пораду як заміну професійній або офіційній консультації.
